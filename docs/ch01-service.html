Chapter 01第 01 章

A service is a function服务就是一个函数

Before the generator, the database and the second protocol, there is one thing to get right: a function that takes a request and returns a response. Everything else is added around it.在生成器、数据库和第二个协议之前，先把一件事做对：一个吃进请求、吐出响应的函数。其余都是围绕它加上去的。

01The contract契约

An ASGI application is a function of three things: a scope describing the request, a receive that hands over the body as events, and a send that takes the response back the same way. That is the whole contract. Every server and framework in this stack speaks it, and nothing above it knows whether the bytes arrived over HTTP/1.1, HTTP/2 or a websocket.ASGI 应用就是一个函数，参数有三样：描述这次请求的 scope，把请求体当作事件交给你的 receive，以及按同样方式送走响应的 send。契约就只有这些。这一栈里的服务器和框架都按它说话，而它上面的代码不必知道字节来自 HTTP/1.1、HTTP/2 还是 WebSocket。

This repository has one entry point, and everything the service does is visible from it:本仓库只有一个入口，服务所做的每件事都能从这里看出去：

src/server/service.mbt
/// Open the database, run the migration, serve until the task is cancelled.
pub async fn serve_greet(
  host~ : String = "127.0.0.1",
  port~ : Int32 = 12000,
  db_path~ : String = "greet.db",
) -> Unit {
  let db = @sqlite.SqliteDriver::open(db_path)
  let sess = @moonorm.Session::new(db)
  @genmodel.user_up(sess) |> ignore
  @mooncat.serve(assemble(sess), host~, port~)
}

Six lines, and four of them are about a database this chapter has not reached. The line that matters today is the last one: assemble builds an application, and @mooncat.serve puts it on a socket. Neither knows what the routes are.六行代码，其中四行在说这一章还没碰到的数据库。今天要紧的是最后一行：assemble 造出一个应用，@mooncat.serve 把它放到端口上。两者都不知道里面有哪些路由。

02Three routes, three spellings三条路由，三种写法

An application is a value. Routes are added to it, and the document that describes them is derived from the same calls — there is no second place to keep in sync.应用是一个值。路由一条条加上去，描述这些路由的文档也从同一批调用推出来 —— 没有第二处需要同步。

src/examples/02-three-styles/function_form.mbt
pub fn function_app() -> @moonapi.App {
  let app = @moonapi.App::new()
  app.get("/ping", ctx => ping(ctx), summary="health check")
  app.get("/greet/{id}", ctx => greet_one(ctx), summary="greet one name")
  app
}
src/examples/02-three-styles/view_form.mbt
// A value answers the path, and carries what the handler needs.
struct Greeter {
  greeting : String
}

fn greet_with(greeting : String, ctx : @moonapi.Context) -> @moonasgi.Response {
  @moonapi.text(200, greeting + ", " + ctx.param("id").unwrap_or("?"))
}

impl @moonapi.View for Greeter with fn get(self) {
  Some(ctx => greet_with(self.greeting, ctx))
}

pub fn view_app(greeting : String) -> @moonapi.App {
  let app = @moonapi.App::new()
  app.get("/ping", _ctx => @moonapi.text(200, "pong"), summary="health check")
  app.view("/greet/{id}", Greeter::{ greeting, })
  app
}
src/examples/02-three-styles/routes.mbt
// The registration is generated: `moonx moonbitstack/moonapi/cmd/routes`
// reads these two functions and writes register(app) into routes.g.mbt.
#app.get("/ping", summary="health check")
fn ping_route(_ctx : @moonapi.Context) -> @moonasgi.Response {
  @moonapi.text(200, "pong")
}

#app.get("/greet/{id}", summary="greet one name")
fn greet_route(ctx : @moonapi.Context) -> @moonasgi.Response {
  @moonapi.text(200, "hello, " + ctx.param("id").unwrap_or("?"))
}
All three are in src/examples/02-three-styles, and a test asserts they answer the same bytes. moon run src/examples/02-three-styles prints one line per form.三种写法都在 src/examples/02-three-styles 里，测试断言三者返回的字节相同。跑 moon run src/examples/02-three-styles 会各打印一行。

The choice is not cosmetic. A function keeps the handler next to its path, which is what you want while the logic is short. A type that answers a path carries state with it, so one value can own a connection or a cache for as long as the route lives. Annotations move the registration into generated code, which is what keeps a route table readable once it has forty entries.三种写法不是好不好看的问题。函数写法把处理函数放在路径旁边，逻辑短的时候最顺手。让一个类型去回答某条路径，可以把状态一起带上，于是一个值能在路由存活期间管住一条连接或一份缓存。注解把注册代码挪进生成物，路由表长到四十条时，靠它才读得下去。

A path parameter is written {id}, and its value arrives through ctx.param. The summary you pass here is the text a reader sees in the API document, because the document is generated from these calls.路径参数写成 {id}，值从 ctx.param 取。这里传的 summary 就是 API 文档里读者看到的那句话 —— 文档由这些调用生成，不是另写的。

03One middleware一个中间件

A middleware takes the next step and returns a new one. It sees the request on the way in and the response on the way out, which is enough to stamp an identifier on every answer without any route knowing it exists.中间件接收「下一步」，返回一个新的下一步。它在入口看到请求，在出口看到响应，因此能给每个响应盖一个标识，而任何路由都不知道它存在。

src/server/service.mbt
app.middleware(async fn(req, next) {
  let resp = next(req)
  @moonasgi.Response::new(
    resp.status,
    [("x-request-id", "greet-1"), ..resp.headers],
    resp.body,
  )
})

The header is prepended, so a route that sets its own x-request-id keeps it. Once the service runs, the check is one flag: curl -i a route that knows nothing about middleware.新头是插在最前面的，路由自己设了 x-request-id 时不会被覆盖。服务跑起来后，验证只要一个参数：对一条完全不知道中间件的路由用 curl -i。

04Run it跑起来

From the repository root. The first command builds and starts the binary on port 12000; the rest are a client.在仓库根目录执行。第一条命令编译并启动二进制，端口 12000；后面几条是客户端。

shell
$ moon run src/cmd/greet-server --target native
$ curl -s localhost:12000/ping
pong
$ curl -s -XPOST localhost:12000/users -d '{"name":"Curl"}'
{"id":1,"name":"Curl"}
$ curl -s localhost:12000/users/1
{"id":1,"name":"Curl"}
The same thing without a socket不占端口也一样
App::handle takes the same request value and returns the same response, through the same middleware. The tests use it; so can you, when starting a server is more ceremony than the question deserves.App::handle 收同样的请求值、返回同样的响应，走的也是同一套中间件。测试用它；当起一个服务器比问题本身还麻烦时，你也可以用。

05What just happened刚才发生了什么

Four libraries took part in that one request, and each had exactly one job:这一次请求里有四个库参与，每个只做一件事：

Layer层Library库Its job here在这里做的事
Transport传输mooncatmooncatAccepted the connection, parsed HTTP, turned it into a scope, and wrote the response back.接连接、解析 HTTP、变成 scope，再把响应写回去。
Contract契约moonasgimoonasgiDefines the request and response values that both sides of the boundary pass.定义边界两侧传递的请求与响应值。
Routing路由moonapimoonapiMatched the path, bound the parameter, ran the middleware, produced the body.匹配路径、绑定参数、跑中间件、产出响应体。
Assembly装配moonzeromoonzeroWrapped the routed application in a service that logs one line per call.把路由装进服务，每次调用记一行日志。

The database appears in serve_greet but not in this table: nothing here has read or written a row yet. That is chapter 2.数据库出现在 serve_greet 里，却不在表里：这一章还没有读写任何一行。那是第 2 章的事。

06Try it动手改

Three changes, easiest first三处改动，由易到难

  1. Change "pong" to "pong!" and run the tests. One goes red, and it is not the one you edited — find it and read what it asserts. That is the loop the rest of the course runs on.把 "pong" 改成 "pong!"，然后跑测试。有一条会红，而且不是你刚改的那条 —— 找到它，读它断言了什么。后面每一章都在跑这个循环。
  2. Add GET /health that answers {"ok":true}, then fetch /openapi.json and find it there. You did not write any documentation.加一条 GET /health，返回 {"ok":true}，再去 /openapi.json 里找它。你一行文档都没写。
  3. Ask for DELETE /ping. It answers 405, not 404, and carries an Allow header. Work out which layer decided that, and why a client cares about the difference.请求 DELETE /ping。它返回 405 而不是 404，还带一个 Allow 头。想想是哪一层决定的，以及客户端为什么在意这个区别。
app.get(
  "/health",
  _ctx => @moonapi.text(200, "{\"ok\":true}"),
  summary="health check",
)
The route the first exercise asks for. scripts/check_site_code.py compiles this block with the two lines above it, so the page cannot teach code that does not build.第一道练习要加的路由。scripts/check_site_code.py 会把它和上面的两行一起编译，所以页面上不会出现编不过的代码。

You can now你现在会了

  • Run the service, call it over a real socket, and read the answer.把服务跑起来、用真实端口调用它，并读懂返回。
  • Say which of the four layers handled one request, and what each of them did.说出一次请求经过了哪四层，每层各做了什么。
  • Write the same route three ways, and say why you would reach for each.把同一条路由用三种写法写出来，并说出各自该在什么时候用。
  • Find the test that a one-word change breaks.改一个字，找出因此变红的那个测试。

The service so far has no memory. Chapter 2 gives it one, and the generator writes the part that touches the database.到这里的服务还没有记忆。第 2 章给它一份，并且由生成器来写碰数据库的那部分。
