Chapter 10第 10 章

The map地图

Ten chapters, one service, nine libraries. What is left is the part a course cannot finish for you: knowing which library answers which question, where the seams are, and what this repository deliberately did not build.十章、一个服务、九个库。剩下的是课程没法替你做完的那部分：知道哪个库回答哪个问题、缝在哪里、以及这个仓库故意没做什么。

01Nine libraries, nine questions九个库，九个问题

Each library answers one question, and the question is the way to remember which one to reach for. The order below is the order a request meets them.每个库回答一个问题，记住问题就记住了该找谁。下面的顺序，就是一次请求遇到它们的顺序。

Library库The question it answers它回答的问题Reach for it when什么时候找它
moonctlmoonctlWhat does the spec say?描述里写了什么？a .api file already describes the service and the types已经有 .api 描述着服务和类型
moonasgimoonasgiWhat is a request, as a value?请求作为一个值是什么？you write a layer that has to run under any host要写一层，且它得能在任何宿主下跑
moonapimoonapiWhich handler answers this path?这条路径由谁回答？routes, typed bodies, an OpenAPI document from the same tree路由、带类型的请求体、由同一棵树生成的 OpenAPI 文档
moonzeromoonzeroWhat does a service add around an app?服务在应用外面加了什么？middleware, config, route options, graceful shutdown中间件、配置、路由选项、优雅停止
moonormmoonormHow does a row become a value?一行怎么变成值？models, sessions, statements, transactions, migrations模型、会话、语句、事务、迁移
moondbmoondbWhat does a database owe a caller?数据库对调用方欠什么？you write a driver, or code that must not care which one要写驱动，或写不该关心是哪个驱动的代码
moonsqlitemoonsqliteWhere do the bytes actually go?字节最后落在哪？a file on disk, no server to run一个磁盘文件，不用起服务器
mooncatmooncatWho owns the socket?socket 归谁？you want native HTTP without another runtime想要原生 HTTP，又不想再拉一个运行时
moongqlmoongqlCan the same data be asked for by shape?同一份数据能不能按形状问？a client wants fields, not endpoints客户端想要字段，而不是接口

moonrpc and moonmuse sit beside this list rather than in it: the first answers the same question over a different wire, the second answers a question that is not about data at all. Chapter 8 runs all eleven lines through one program if you want them side by side.moonrpc 和 moonmuse 在这张表旁边而不是表里：前者用另一根线回答同一个问题，后者回答的根本不是数据的问题。想把它们并排看，第 8 章用一个程序跑了十一行。

02Where the seams are缝在哪里

Every chapter in this course changed one seam and left the others alone. There are four of them, and each is a value rather than an inheritance: you can build one by hand, hand it to the next layer, and nothing above or below needs to know.这门课每一章只动一条缝，其余不动。缝有四条，每一条都是一个值而不是一层继承：你可以自己造一个，交给下一层，上面和下面都不需要知道。

Seam缝The value that crosses it跨过它的值What can be replaced behind it后面可以换掉什么
spec → code描述 → 代码@moonctl.parse and the text it writes@moonctl.parse 和它写出的文本the generator, or the model written by hand生成器，或者手写的模型
app → transport应用 → 传输AsgiAppAsgiAppmooncat for a socket, a test client for none要 socket 就用 mooncat，不要就用测试客户端
model → database模型 → 数据库&@moondb.Driver&@moondb.DriverSQLite here, Postgres or MySQL behind the same session这里是 SQLite，同一个会话后面换 Postgres 或 MySQL
app → surface应用 → 入口the same handler, mounted twice同一个处理器，挂两次REST, GraphQL and gRPC answering one functionREST、GraphQL、gRPC 回答同一个函数

The tests in this repository live on those seams rather than on the handlers: a request through a real socket, a row through a real table, a gRPC call discovered by reflection. That is why a version skew between two libraries shows up here as a red build instead of as a bug report.这个仓库的测试守的是这些缝，而不是处理器：请求走真 socket，行走真表，gRPC 先反射发现再调用。所以两个库之间的版本错位，在这里表现为一次红的构建，而不是一张 bug 单。

03What this repository does not build这个仓库没做什么

A course that only shows what works is a brochure. These are the parts left out on purpose, so that the parts included stay readable.只展示能跑的部分，那是宣传册。下面这些是故意留白的，好让写出来的部分还读得下去。

  • No authorization model. A token is checked; who the caller is and what they may do is a separate design.没有权限模型。令牌被校验了；调用者是谁、能做什么，是另一套设计。
  • No migration history. migrate creates the table; changing a column in place is what moonorm's migration package is for.没有迁移历史。migrate 只建表；原地改列是 moonorm 的迁移包负责的事。
  • No pool tuning and no health checks. Both exist in the stack; neither is what this course is about.没有连接池调优，也没有健康检查。两样在栈里都有，但都不是这门课的主题。
  • No deployment. The module is pinned to native because it listens on a socket and links SQLite; shipping the binary is a platform decision, not a library one.没有部署。模块钉在 native，因为它监听 socket 又链接 SQLite；怎么发这个二进制是平台的决定，不是库的决定。

04From the outside从外面调

Every chapter called the service from inside the module. src/examples/06-clients calls it the way another program would, over a real socket, and adds a layer on the way: an MCP endpoint on the same listener, so an agent can ask for the same greeting.前面各章都是在模块内部调这个服务。src/examples/06-clients 照别的程序的方式，经真实的套接字从外面调；顺带加了一层：在同一个监听上挂一个 MCP 端点，让智能体也能要到同一句问候。

src/examples/06-clients/main.mbt
  let app = @dispatch.mount(
    [("/mcp", greeter().to_asgi(path="/", docs=None))],
    fallback=@server.assemble(sess),
  )

@dispatch.mount picks an application by path prefix: /mcp goes to the MCP server, everything else to the service the chapters built, which does not change by a line. The clients are moonfetch for HTTP and GraphQL and moonmcp's own client for the tool:@dispatch.mount 按路径前缀选应用：/mcp 交给 MCP 服务，其余交给前面各章搭起来的服务，那边一行不改。客户端是 moonfetch（HTTP 与 GraphQL）和 moonmcp 自带的客户端（调工具）：

src/examples/06-clients/main.mbt
    let mcp = @client.Client::connect(@http.Http::new(base + "/mcp"))
    let answer = mcp.call_tool("greet", arguments={ "name": "Ada" })

The repository is the rest of the map: src/examples/ has one program per idea, src/server/ is the service the chapters build, and README.md lists the thirteen libraries in the order a request meets them. Every code block in this course is compiled in CI, so a page that drifts from the source fails the build before it reaches you.仓库就是地图的其余部分：src/examples/ 一个想法一个程序，src/server/ 是各章搭起来的那个服务，README.md 按请求经过的顺序列着十三个库。这门课里每个代码块都在 CI 里编译，所以页面一旦和源码脱节，在到你手里之前构建就已经红了。

You can now你现在会了

  • Name the library by the question you have, not by the feature you want.用你手上的问题去找库，而不是用你想要的功能。
  • Point at the seam a change belongs on, and say what crosses it.指出一处改动该落在哪条缝上，并说出跨过它的是什么值。
  • Say which parts of a stack are the application's job and which are the platform's.说出一套栈里哪些是应用的事、哪些是平台的事。
  • Start a service of your own from the same four values.用同样的四个值起一个你自己的服务。
