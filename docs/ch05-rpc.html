Chapter 05第 05 章

A third surface第三个门面

The same greeting over gRPC: one proto file, one handler that turns bytes into bytes, and Server Reflection so a client can discover the service before it calls.同一句问候走 gRPC：一份 proto、一个把字节变成字节的处理函数，加上 Server Reflection，让客户端先发现服务再调用。

01The contract契约

The proto file is the contract, and it is read twice: by people, and by the descriptor the server registers for reflection.proto 文件是契约，被读两次：人读一次，服务为反射注册的描述符再读一次。

src/spec/greet.proto
syntax = "proto3";

package greet;

// The gRPC leg of the greet end-to-end slice: a Greeter served over moonrpc's
// self-built h2c transport with Server Reflection, so a reflection client
// (grpcurl, or the in-process Channel client the test uses) can list, describe,
// and call it.
service Greeter {
  rpc SayHello (HelloRequest) returns (HelloReply);
}

message HelloRequest {
  string name = 1;
}

message HelloReply {
  string message = 1;
}

This repository builds the descriptor by hand, three small constructors per message, rather than running protoc at build time. The test asserts that the descriptor and the encoded bytes agree, so the two readings of the contract cannot drift apart unnoticed.本仓库手写描述符 —— 每个消息三个小构造子 —— 而不是在构建时跑 protoc。测试断言描述符与编码后的字节一致，于是契约的两种读法不会悄悄分家。

02One handler一个处理函数

A gRPC method is bytes to bytes. The handler reads the request, greets, and writes the reply; a malformed request decodes to an empty name rather than an error, which is proto3's default and not a decision this code makes.gRPC 方法就是字节到字节。处理函数读请求、问候、写回复；请求损坏时解出的名字是空串而不是报错 —— 这是 proto3 的默认值，不是这段代码的决定。

src/rpc/greeter.mbt
fn say_hello(request : Bytes) -> Bytes {
  let name = parse_hello_request(request) catch { _ => "" }
  hello_reply("Hello, " + name)
}

The reader is a loop over tags, and an unknown field number is skipped rather than refused. That is what lets a message grow: an old server reads a new client's request and ignores what it does not know.读取器是一个按 tag 的循环，不认识的字段号会被跳过而不是拒收。消息因此才能长大：旧服务读新客户端的请求，忽略自己不认识的部分。

03Serving提供服务

Five statements: a server, the method path, a reflection service, the descriptor in it, and the accept loop. The handler is registered by path, the way gRPC addresses a call.五条语句：服务器、方法路径、反射服务、把描述符放进去、进入接受循环。处理函数按路径注册 —— gRPC 就是这样寻址一次调用的。

src/rpc/greeter.mbt
  let server = @net.GrpcServer::new()
  server.register("/greet.Greeter/SayHello", say_hello)
  let refl = @moonrpc.ReflectionService::new()
  refl.add_file(greet_descriptor())
  server.register_reflection(refl)
  server.serve(host~, port~)

04Discover, then call先发现，再调用

Reflection is what a client needs to call a service it was not handed the proto for. grpcurl uses it for list, describe and the call itself; this repository's own client uses the same three steps over a real socket.客户端没有拿到 proto 时，就靠反射来调用服务。grpcurl 用它做 list、describe 和调用本身；本仓库自己的客户端也在真实 socket 上走同样三步。

shell
$ grpcurl -plaintext localhost:12001 list
greet.Greeter
$ grpcurl -plaintext localhost:12001 describe greet.Greeter
service Greeter {
  rpc SayHello ( .greet.HelloRequest ) returns ( .greet.HelloReply );
}
$ grpcurl -plaintext -d '{"name":"Ada"}' localhost:12001 greet.Greeter/SayHello
{
  "message": "Hello, Ada"
}

The tests drive that path with Channel::connect: a server-streaming call for reflection, then a unary call for SayHello. The leg is exercised end to end, not only compiled.测试用 Channel::connect 走这条路：先做一次服务端流式调用拿反射，再做一次一元调用打 SayHello。这条腿是端到端跑过的，不只是编过。

05When the method is not there方法不在的时候

An unknown method is UNIMPLEMENTED (12): a status on the call, not a broken connection. The next call on the same channel still works, which is the difference between a refusal and a crash.未知方法是 UNIMPLEMENTED（12）：这是调用上的状态，不是连接坏了。同一条通道上的下一次调用照样成功 —— 这就是「拒绝」和「崩了」的区别。

src/rpc/greeter_test.mbt
    let missing = ch.unary("/greet.Greeter/Shout", @rpc.hello_request("Ada"))
    assert_eq(missing.grpc_status, 12)

06Try it动手改

Three changes, easiest first三处改动，由易到难

  1. Add a field times = 2 to HelloRequest, regenerate the descriptor by hand, and call it with grpcurl without touching the server. The old reader skips the field it does not know.给 HelloRequest 加一个 times = 2 字段，手改描述符，然后用 grpcurl 调它 —— 服务端一行不改。旧的读取器会跳过自己不认识的字段。
  2. Add Shout to the service and remove it again. The status goes from 12 to 0 and back; the client code does not change.在服务里加 Shout，再删掉。状态从 12 变成 0 又变回去，而客户端代码一行没动。
  3. Call a method on the wrong service name (greet.Greeter2/SayHello) and read the status. Then find the line in serve_greet_grpc that decides it.用错的服务名调用（greet.Greeter2/SayHello），读返回状态。然后到 serve_greet_grpc 里找出决定它的那一行。

You can now你现在会了

  • Read a proto file and say which message a method takes and returns.读懂 proto，说出一个方法收哪个消息、回哪个消息。
  • Explain what Server Reflection saves a client from doing.解释 Server Reflection 省掉了客户端的哪一步。
  • Tell a gRPC status from an HTTP status, and give one example of each.分清 gRPC 状态与 HTTP 状态，各举一例。
  • Serve the same service from a binary and call it from outside that process.用二进制把服务跑起来，并从进程外调用它。
